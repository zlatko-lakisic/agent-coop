Project rule, plus a project stop hook in .cursor/hooks.json. The hook runs agentcoop hook cursor-stop. A beforeSubmitPrompt hook runs agentcoop hook cursor-prompt and records the new prompt. The default timeout is 3600 seconds, from cursor_hook_timeout_seconds, and 3600 is the longest Cursor accepts without a warning. It waits until 5 seconds are left. If this agent has done anything since the hook started, it sends nothing. If mail is waiting and the chat is idle, it sends that mail and tells the driver to continue. If the wait ends with no mail, it sends: Agent Co-op keep-awake. If you are working on anything, ignore this and keep going. Otherwise end your turn. The transcript shape was checked against Cursor 3.27.14. A user line counts as a new turn only when it has a user_query that is not Cursor's shell-task notice. A user line that is only a timestamp does not. If transcript_path is missing, unreadable, or has no line Agent Co-op recognizes, the trace and agentcoop doctor say: Cursor's transcript format is not recognized. A stale hook may interrupt work. The stop hook reads only the new bytes of the transcript. If mail has waited more than twice the progress interval and there has been no tick, hook follow-up, or agentcoop command since it arrived, STATUS.md and doctor say Cursor has not picked up mail for N min, and the next stop hook sends that mail even if the transcript looks like a new turn. loop_limit is unlimited so mail can keep waking the chat. sessionStart cannot start a command, so the rule starts cursor-loop. A tick wakes the chat only when the agent is watching AGENT_LOOP_TICK_board. A finished background command wakes the agent while a turn is still running. After the turn ends the shell can die, and a Cursor restart kills it, so the stop hook is the other wake. On 2026-10-27, cursor -n --chat was opened on a throwaway folder on this Windows PC. No command ran in that chat, the stop hook wrote no log line, and no AGENT_LOOP_TICK_board line was printed. Computer use could not type into that window. This session did not see a tick start a turn, and it did not see the older macOS wake either. The Start working flow in an existing Cursor window is untested on macOS and Linux. When the chat is not watching, Cursor waits for Start working. Other tools still run in the background. Say Run the driver in the background when the chat is idle to change Cursor. notify_when_idle is off. A notification is not sent unless that setting is true. Before a driver run, Agent Co-op writes <worktree>/.cursor/cli.json so the agent may read broadly, write only the worktree and the board, and run git, agentcoop, agentcoop.exe, agentcoopw.exe, agentcoop.cmd, and the commands in driver_shell_allow. Before a helper run, it writes <board>/projects/<project>/.cursor/cli.json with Read(**) allowed and Write(**) and Shell(*) denied. Permissions: https://cursor.com/docs/cli/reference/permissions A person's ~/.cursor/cli-config.json may also hold permissions. How the two files combine is not documented, so keep broad allow rules out of the global file. Sign in with agent login. https://cursor.com/docs/cli/reference/parameters After Start working, the Cursor driver starts agentcoop cursor-loop in the background and watches for AGENT_LOOP_TICK_board. Helpers still use agentcoop watch. Cursor waits about 30 seconds for a foreground command, then moves it to the background. It does not kill that command. Shell Mode in the CLI kills a command at 30 seconds and that limit cannot be changed: https://cursor.com/docs/cli/shell-mode The default watch wait is 10 minutes, which fits because the command runs in the background. There is no documented cap on how many steps one desktop turn may take. If a turn ends and cursor-loop is not running, the driver starts it again. The person says Start working only when the driver cannot start it. Connecting Cursor writes <project>/.cursor/permissions.json with agentcoop on terminalAllowlist. The app also reads ~/.cursor/permissions.json. https://cursor.com/docs/reference/permissions A full path does not match the short name, so copy the exact command from a prompt into that file if one still appears. Headless agent -p can abort leftover background commands after the turn when you pass --background-shell-timeout. https://cursor.com/docs/cli/changelog Terminal tool: https://cursor.com/docs/agent/tools/terminal A cursor-loop tick was not observed to start a new turn in the app chat on this Windows PC. Do not end the turn while a task is open. The stop hook can hand over mail, or a continue follow-up when a task is still open, only while it is still waiting. A cursor-loop heartbeat does not cancel that follow-up. After the turn has ended, cursor-loop still posts helper files and does not print a continue tick.
